# Project brief: topology-aware segmentation of rock micro-CT, scored by flow

This file is the standing brief for Claude Code. Read it at the start of every session.
The owner is a solo researcher with CCTA segmentation experience and no rock background.
Explain rock-specific terms the first time you use them in any report.

## 1. The question

Port a 2026 coronary study ("Same Branches, Different Trees", arXiv 2607.28327) to digital rock.

- **Q1 (metrics).** Which segmentation metric best predicts permeability error:
  Dice, clDice, Betti-number error, Euler-number error, or throat-level error?
- **Q2 (losses).** Do topology-aware losses (soft-clDice, Skeleton Recall) reduce
  permeability error at equal Dice, compared with Dice + cross-entropy?
- **Q3 (regime).** Does the answer change with image resolution and porosity?

**Framing (from the Gate 0 review, 12 Nov 2026).** The idea is not new: Wang et al. 2021
(arXiv 2002.05322) showed high voxel accuracy with wrong permeability and suggested using
connectivity or approximate flow as a loss. This project is the first systematic TEST of
that suggestion, not a new idea. Always cite Wang et al. as the origin.
Status after review: Q2 open (moderate confidence, absence-of-evidence), Q1 and Q3 partly
done. A null result in clean, high-porosity sandstone is expected and is publishable.

**Centre of gravity (decided 12 Nov 2026).** The paper's core is the CPU perturbation
study (Phase 3): "Which segmentation errors matter for permeability in digital rock?"
The trained-model comparison (Phase 4) is a slim second part that checks whether the
findings carry over to real network errors. The project must be publishable from Phases
0 to 3 alone. Do not let Phase 4 hold up or reshape the core.

Working hypothesis, to be tested and not assumed: pore networks are full of loops, so a
single broken connection matters less than in a coronary tree. Topology should matter most
near the percolation threshold (low porosity, coarse resolution), and throat calibre should
matter most elsewhere. Either outcome is a result.

## 2. Rules that override everything else

1. **Gates (section 4).** The owner wants minimal interruptions, so:
   - Gates 0, 1 and 2 are **report-and-continue**: write the gate report to
     `docs/gates/`, log it in the lab notebook, give the owner a five-line summary, and
     carry on. Phases 0, 1 and 2 may run in parallel.
   - **Hard stops, always wait for the owner:** (a) any paper found that already answers
     Q2 or the core perturbation question; (b) any download over 20 GB; (c) the Kaggle
     token is needed and missing; (d) before the Phase 3 batch runs; (e) before any Phase 4
     GPU run (this also needs the owner's explicit Gate 0 approval of `docs/novelty.md`);
     (f) before anything is posted or submitted.
   - No "first to do this" wording anywhere until the owner has approved Gate 0.
2. **Never state a number you did not compute in this repository.** Every figure and table
   is generated by a script under `analysis/`, from files under `results/`.
3. **Never claim novelty yourself.** Novelty statements come only from `docs/novelty.md`,
   which the owner signs off at Gate 0.
4. **Report null and negative results in full.** Do not tune until something is significant.
5. **Fix the analysis plan before looking at test data** (`docs/prereg.md`, Gate 1).
6. **Splits are by rock sample, never by patch.** No sample appears in both train and test.
7. **Seeds:** three per configuration, recorded. Report mean and spread.
8. **Cite only papers you have opened.** Keep `docs/refs.bib` with a one-line note per entry
   saying what you verified in it.
9. Verify every dataset's licence, size and URL before downloading. Record them in
   `data/MANIFEST.md`. If a detail in this brief turns out wrong, say so and correct it here.
10. Ask before any download over 20 GB or any Kaggle run over 6 hours.

### Phase 1: data and pre-registration  →  Gate 1
- **Primary dataset:** "11 Sandstones", Digital Rocks Portal project 317
  (doi 10.17612/f4h1-w124). 11 samples, 1000³ voxels, 2.25 µm, with raw,
  filtered and segmented volumes and lab permeability (all confirmed 2026-11-12).
  *Corrected 2026-11-12:* the segmentation is a single global **IsoData** threshold per
  sample on the filtered image (Data in Brief descriptor; thresholds per sample in
  `data/MANIFEST.md`). "Watershed" was only Neumann et al.'s network extraction. The
  published masks keep isolated pores; Neumann et al.'s porosity/permeability use the
  connected pore space only. Licence ODC-BY 1.0. The Digital Rocks Portal has moved; files
  are per-file downloads from TACC Web Corral (URLs in the manifest). Each volume is
  953.6 MiB: the 11 segmented volumes are 10.2 GiB, all 33 volumes 30.7 GiB (over 20 GB).
- **Secondary:** IBM microCT dataset (Scientific Data 2023) for carbonates and low
  permeability; Imperial College images and networks for pore-network cross-checks.
  *Corrected 2026-11-12:* IBM data licence is CDLA-Sharing-1.0 (not CC BY), 1.53 TB in
  total, GitHub repo gone (404); only the binary 2500³ ROI cubes are practical. Imperial
  2015 images are 1000³ (not 300–400³ crops), no licence stated; the 2007 set is CC BY 4.0.
- **Conditional robustness check:** MRCCM paired low/high-resolution carbonate scans
  (Alqahtani et al. 2022), to test whether synthetic degradation resembles real
  low-resolution scans. Use it only if the data is downloadable and a pore/grain label is
  defensible there (carbonates have pores smaller than a voxel). It never gates the paper.
- Licences, download sizes and URLs verified 2026-11-12 from the source pages; see
  `data/MANIFEST.md` (checksums are filled at download).
- Use all 11 sandstones if resources allow, at least 3 held out for test, and make sure
  the low-porosity samples are represented in both train and test.
- Crop sub-volumes (start at 256³, then 400³ if resources allow).
- **Reference labels** come from the high-resolution published segmentation.
- **Hard regime:** `degrade.py` makes low-resolution inputs from the high-resolution
  greyscale (blur, downsample by 2x and 4x to about 4.5 and 9 µm, add noise), mirroring
  the 2, 4 and 8 µm of Saxena et al. 2017 (*2026-11-12: these Saxena 2017 details are
  unverified, the paper could not be opened; do not cite them until it is. Saxena et al.
  2018 (abstract) gives "at least 10 voxels" across a throat for flow*). Labels stay at the reference topology,
  resampled consistently. Document the exact procedure. Report voxel size relative to
  throat radius. Also erode reference masks to approach the percolation threshold.
- **Label resampling check:** resampling a mask can itself open or close throats. For
  every resampling method considered, measure the change in Betti numbers, throat count
  and permeability of the label alone, and choose the method that changes them least.
  Report these numbers in the paper.
- Write `docs/prereg.md`: metrics, primary outcome (log ratio of predicted to reference
  permeability), statistical tests, and what would count as support for each hypothesis.
- **Gate 1:** owner approves the manifest and the pre-registration.

### Phase 2: CPU pipeline  →  Gate 2
- `network.py`: PoreSpy SNOW2 extraction. `flow.py`: OpenPNM single-phase permeability
  in three directions.
- Cross-check on a few sub-volumes with a voxel-based solver (lattice-Boltzmann or
  Stokes). Report the disagreement between the two.
- `tests/`: analytic cases (straight tube, parallel plates) must match theory.
- **Solver uncertainty:** run a grid-refinement study on at least three sub-volumes and
  report the solver's numerical error. Effects smaller than that error are not reported
  as findings.
- `metrics.py`, in three tiers fixed in `docs/prereg.md` before any analysis:
  - **Primary (hypothesis tests):** Dice, porosity error, Euler-number error, Betti
    error (0 and 1), clDice, throat-level error (one-to-one matching by distance: missed
    throats, false throats, radius error).
  - **Secondary (reported, no headline claims):** connected-porosity error, distance
    between pore- and throat-size distributions, IoU.
  - **Exploratory (appendix, labelled as such):** the remaining Minkowski functionals,
    graph max-flow (after Gärttner/Alpak 2023), formation factor.
  Correct for multiple comparisons across the primary tier. Build and validate the
  primary tier first; add the others only once it is tested.
- Permeability claims rest on the voxel solver; the pore network is used for throat
  matching and as a second estimate. Report where the two disagree.
- Baselines: Otsu, IsoData and watershed on full-resolution and degraded inputs.
- **Gate 2:** a short report showing the pipeline reproduces published permeability for
  at least one benchmark sample to within the range reported in the literature.

### Phase 3: perturbation study, no GPU (answers Q1)  →  Gate 3
- Apply controlled errors to reference masks: global erosion and dilation; errors placed
  only at throats; errors placed only in pore bodies; random closures of single throats;
  false bridges through thin grain contacts. Several magnitudes each.
- **Headline experiment, topology versus geometry:** a factorial design crossing
  (a) broken connections (throats closed, widths untouched) with (b) narrowed throats
  (widths reduced, connections intact), at matched porosity change where possible, across
  porosity levels and resolution levels. The main figure shows which error type causes the
  larger permeability error in each regime, and whether the two interact.
- For every perturbed mask compute all metrics and the permeability error.
- Analysis, following arXiv 2607.28327: rank correlations, a joint regression with all
  metrics entered together, bootstrap confidence intervals resampled by sample.
- Report |log10(k_pred / k_ref)| and signed bias. Always give partial correlations
  controlling for porosity error, since porosity is the obvious confound.
- **Gate 3:** results memo. Owner decides whether Q1 alone already merits a short paper.

### Phase 4: trained models on Kaggle (answers Q2 and Q3)  →  Gate 4
- **Core comparison (must run):** 3D U-Net (MONAI), patch-based, mixed precision, with
  Dice+CE versus Dice+CE + Skeleton Recall. Three seeds each, at two degradation levels.
- **Only if GPU budget remains:** + soft-clDice, weighted CE (as in Wang et al.), a third
  degradation level.
- Use the Phase 3 result to interpret Phase 4: do the trained models make the error
  types that Phase 3 found to matter, and does the loss reduce those specifically?
- Skeleton Recall comes first: its authors report about 8% extra training time and 2%
  extra memory, against about 88% and 52% for clDice. Run soft-clDice on smaller patches
  if it does not fit. A persistent-homology loss is optional and only on small patches.
- Also report nnU-Net defaults if the budget allows.
- Post-hoc control: keep only the largest sample-spanning pore cluster of each baseline
  prediction, to show whether a loss does anything a simple filter cannot.
- Match Dice across losses where possible, so differences are not just overlap.
- Known weakness to measure, not hide: a patch-wise loss cannot see a break that only
  matters for sample-spanning flow.
- Kaggle workflow: `kaggle kernels push`, poll with `kaggle kernels status`, fetch with
  `kaggle kernels output`. Checkpoint every epoch to the output directory and resume, since
  sessions are time-limited. Track GPU-hours used against the weekly quota.
- Evaluate on held-out samples with the Phase 2 pipeline, on CPU.
- **Gate 4:** results tables with all seeds, before any writing.

### Phase 5: paper  →  Gate 5
- Structure: introduction and gap; data and degradation; metrics; perturbation study;
  loss comparison; regime analysis; limitations; reproducibility statement.
- Limitations to state plainly: simulated versus lab permeability; scale mismatch with
  core plugs; sandstone only unless carbonates were added; reference labels are themselves
  threshold-based.
- Run a separate reviewer pass in a fresh session that has not seen the work: its job is
  to break the claims. Log its objections and the responses.
- Include an AI-assistance disclosure. The owner is the accountable author.
- **Gate 5:** owner reads the full draft and every figure before anything is posted.

## 6. Compute budget

- **The owner's PC must never be left running long jobs.** Hard cap: no local job over
  1 hour. Anything longer goes to Kaggle (CPU notebooks for network extraction and metrics,
  GPU notebooks for the voxel solver and training), pushed with the Kaggle API so it runs
  on Kaggle's servers with the PC switched off.
- **Benchmark before every batch:** time one mask end to end, multiply out, and tell the
  owner the expected total hours and where it will run. No batch starts without that
  number.
- Local: mini PC and laptop, CPU only, for writing code, unit tests and small trials.
- Kaggle free GPU for Phase 4 only. Estimate GPU-hours before each batch of runs and
  cut the grid (fewer degradation levels first, never fewer seeds) if it does not fit.
